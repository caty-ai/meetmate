# Hosted hub（クラウド調停）のセットアップ

## このドキュメントについて

このドキュメントは、hosted hub を使う Meetmate 利用者・運用者向けのセットアップガイドです。

hosted hub は、複数のエージェントが同じ会議で同時に喋らないための調停を提供します。自分でハブを立てずに、この調停を利用できます。

既存の self-hosted 構成は変わりません。`HUB_URL` と `HUB_SHARED_TOKEN` を使う接続方法も引き続き利用できます。

---

## 初回セットアップ（1 回だけ）

1. Meetmate を起動し、設定 UI の「接続テスト」タブにある **Cloud arbitration** パネルを開きます。最初はステータスが「確認中」と表示され、確認後に現在の接続状態へ切り替わります。
2. 「接続」を押します。通常は認証ページがブラウザで開きます。開かない場合は「ブラウザが開かない場合: 認証ページを開く」のリンクを押します。
3. ブラウザで Google にサインインします。認証後は `127.0.0.1` の loopback ページへ戻り、Meetmate が一度限りの setup code を自動で交換して接続を完了します。
4. Cloud arbitration のステータスが「接続済み」になったことを確認します。「クラウド調停は会議参加時に自動で有効になります。」と表示されれば、以後の会議でセットアップ操作は不要です。

接続時には、hosted hub の接続先、プラン、installation ID、有効期限、room salt とそのバージョンなどが `config.json` に保存されます。hub token と room salt は class-1 credential として扱われ、設定 UI では実値を表示せずマスクされます。

運用者は、既存の hosted 設定で使う hub token を OS の起動環境に `HUB_TOKEN` として指定することもできます。この方法でも hosted hub の接続先と room salt などの設定は必要です。設定 UI の「切断」はプロセスの起動環境を変更しないため、起動環境の `HUB_TOKEN` は削除されません。

---

## 会議参加（毎回・操作なし）

hosted hub に接続済みであれば、会議への参加時にクラウド調停が自動で有効になります。調停のために押すボタンはありません。

Meetmate は会議 URL と room salt から HMAC-SHA256 で room code を導出します。hub へ送るのはこの room code であり、会議 URL の生値が端末の外へ出ることはありません。

参加後は、ダッシュボードの通話中カードにある「調停」の表示を確認してください。`READY` なら調停中です。Meet チャットにも「調停ON」で始まる状態が投稿され、room と members 数を確認できます。

hosted hub の設定は通常 24 時間ごとに更新対象となり、古くなっていれば状態確認時または会議参加時に自動更新されます。すぐに最新の設定を取得したい場合は、設定 UI の Cloud arbitration パネルで「設定を更新」を押します。更新に失敗した場合は、最後に正常取得できた設定が維持されます。

---

## 調停が止まったときの見方

次のどの場合も、Meetmate 自体は会議から退出せず参加し続けます。`auth_failed`、プラン上限、2 時間上限による terminal 拒否では muted-degraded となり、自動発話だけを止めます。`proto_mismatch` と `hub_unavailable` は DEGRADED ですが muted-degraded ではないため、表の復旧方法に従ってください。

| 表示（Meet チャット） | 意味 | できること | 会議には居続けるか |
|---|---|---|---|
| `auth_failed`<br>「[名前] は調停に参加できません（設定の確認が必要です）」 | hub token が無効・失効しているか、必要な scope がありません | 設定を確認してください | はい（自動発話だけ停止） |
| `plan_meeting_quota`<br>「調停OFF（今月の無料枠 5/5 を使い切りました）。この会議では自動発話を停止します」 | 当月の会議回数を使い切りました | 翌月まで待つか、プランをアップグレードしてください | はい（自動発話だけ停止） |
| `plan_agent_limit`<br>「[名前] は調停に参加できません（この部屋の同時エージェント上限 2体）」 | この部屋の同時エージェント上限に達しました。すでに調停中のエージェントはそのまま継続します | プランをアップグレードしてください | はい（拒否されたエージェントは自動発話だけ停止） |
| `plan_room_limit`<br>「調停OFF（同時に開ける会議は1つまで）」 | アカウントの同時会議数上限に達しました | プランをアップグレードしてください | はい（自動発話だけ停止） |
| `room_expired`<br>「2時間の上限に達したため調停を終了しました（入り直すと次の1回としてカウントされます）」 | このアカウントの 2 時間の利用上限に達しました | 会議へ入り直すと再開できます | はい（自動発話だけ停止） |
| `proto_mismatch`<br>「調停OFF（プロトコル不一致・meetmate の更新が必要です）」 | Meetmate と hub のプロトコルが一致していません | Meetmate を更新してから、会議へ入り直してください | はい（調停は停止。muted は保証されません） |
| `hub_unavailable`<br>「調停OFF（クラウド調停に接続できません・自動で再試行します）」 | hosted hub またはクラウド側へ一時的に接続できません | 自動再試行します。続く場合は設定を確認してください | はい（再試行中も会議への参加を継続） |

---

## 「調停なしで続行」ボタン

「調停なしで続行」は、調停クライアントが muted になった terminal 拒否のときに、ダッシュボードの通話中カードへ表示されます。拒否時の `roomOccupied` が `true` か `false` かには依存しません。`hub_unavailable` や `proto_mismatch` のように muted ではない状態では表示されません。

このボタンを押すと、その会議で muted 状態を解除し、hosted hub の調停を使わずに自動発話を続けます。ほかのエージェントとの同時発話を防ぐ保証はなくなるため、会議の状況を確認したうえで使用してください。

サーバーに `JOIN_SHARED_TOKEN` が設定されている場合、最初のリクエストは認証情報がなければ `401` となり、ページに「参加トークン（JOIN_SHARED_TOKEN）を入力してください」と表示されます。入力した token は同じブラウザセッションの `sessionStorage` に保存され、再リクエストに使われます。

---

## 解除（切断）

設定 UI の Cloud arbitration パネルで「切断」を押すと、通常は次の処理が行われます。

| 対象 | 処理 |
|---|---|
| クラウド側 | 現在の hub token を使って自分自身の installation を失効させます |
| ローカル | 保存済みの hub token、installation ID、hosted hub 接続先、room salt、room salt version、plan ID、有効期限、設定更新時刻と更新間隔のキャッシュを削除します |
| self-hosted 設定 | `HUB_URL`、`HUB_SHARED_TOKEN` などの shared-mode 設定は変更しません |
| 起動環境 | OS の起動環境にある `HUB_TOKEN` は削除しません |

クラウド側の失効に失敗した場合、設定 UI はローカル資格情報だけを削除するか確認します。再接続するときは、もう一度「接続」を押して Google サインインを完了してください。

## プランと回数

| プラン | `hub_agent_slots` | 同時会議 | 月次回数 |
|---|---:|---:|---:|
| Free | 2 | 1 | 5 |
| Personal | 2 | 1 | 20 |
| Pro | 3 | 1 | 無制限 |
| Team | 5 | 3 | 無制限 |

1 回 = 1 会議 = 2 時間まで。参加した各アカウントにそれぞれ 1 回として数えます

同じアカウントの 2 体目、再接続、hub の再起動やデプロイでは回数は増えません。2 時間の利用枠が終わったあとに同じ会議へ入り直すと、新しい 1 回として数えます。アップグレードは「次の会議から反映されます」。

## 送るもの・送らないもの

| 流れる | 流れない |
|---|---|
| `roomCode`（会議 URL の HMAC・**生 URL ではない**） | 音声 / PCM |
| `agentId` / `displayName` / `wakeWords`（エージェントの呼び名） | 文字起こし・**発話テキストの本文** |
| **`clientInstanceId`**（インストール単位で安定した識別子。同一インストールが参加したすべての会議を hub 側で紐づけられる） | LLM の入出力・プロンプト |
| 順位票 `hits:[memberId...]`（**誰の名前が先に出たかの並びだけ**） | 会議参加者の氏名・メールアドレス |
| **調停ログの `matchedWords`（＝実際に発話された呼びかけ語そのもの）**（調停ログの契約フィールド） | カード情報（Stripe 側のみ・caty-cloud も hub も保持しない） |
| floor の要求／許可／解放・`speech` の started/ended・`tailMs` | 会議 URL の生値 |
| アカウントトークン（入場時） | — |
| **admission 応答由来の `account_id` / `plan_id` / `meeting_id`**（hub のメモリと JSONL に載る） | — |

`hits` は memberId の配列であり、語そのものではありません。ただし調停ログの `arbitration_round.matchedWords` には、実際に発話された呼びかけ語が記録されます。正確には次のとおりです。

発話テキストの本文は hub に届かないが、実際に発話された呼びかけ語は調停ログ（`arbitration_round.matchedWords`）に記録される

**同じ部屋の他の参加者へ再配布されるもの**: `welcome.members[]` と `member_joined` により、あなたのエージェントの `displayName` と `wakeWords` は、同じ会議 URL から導出された room を共有する全員へ送られます。
