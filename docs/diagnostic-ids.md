# 診断 ID 一覧 / Diagnostic IDs

`MM-<AREA>-<NNN>`: AREA は役割を表す英大文字 3 文字、NNN は原因を表す 3 桁です。  
原因番号の百の位は設定・プロバイダー・到達性・本体状態・会議中の失敗を区別し、HTTP ステータス番号ではありません。

ID の定義元は [src/settings/diagnostic-id.js](../src/settings/diagnostic-id.js) です。**ID は追記のみで、意味を変更せず、再利用しません。** / IDs are append-only and never reused.

領域は STT（音声認識: Soniox / Deepgram）、TTS（音声合成: Fish Audio / ElevenLabs / OpenAI-compatible）、LLM（AI）、ATT（Attendee）、TUN（公開 URL）、DSC（Discord）、SLK（Slack）、MMT（meetmate 本体）です。既知の system があれば静的検証でもその領域を使います。たとえば Soniox の必須値不足は `MM-STT-002` です。SET（初期設定）は、system が無い・未知の場合の静的検証だけに使います。それ以外の未知の system は MMT になります。

表は純関数が返せる全組み合わせを列挙しています。すべての組み合わせが現在の画面から発生するわけではありません。特に 103 は現在 LLM、104 は Discord、202 は公開 URL、510–512 は LLM の会議中タイムアウトログで使います。`MM-LLM-510` / `MM-LLM-511` / `MM-LLM-512` は音声では読み上げません。SLK は現在 readiness の参加判定外です。

`MM-*-209` と `MM-*-301` の `*` は下の行に列挙した領域の省略表記です。未知の code は同じ領域の 209 に落ちます。`CONNECTED` と空の code の ID は `null`（表示なし）です。`{provider}` は対象プロバイダーの表示名を表し、設定値ではありません。既存の設定リンクから該当項目を開けます。詳しい操作は [セットアップガイド](setup-guide.md) を参照してください。

v1 の表示面は readiness JSON・メイン画面・設定画面の readiness サマリ・readiness 由来の参加失敗・LLM タイムアウトログです。接続テストの API はまだ ID を返さないため、その結果行は現状のままです（将来 ID が届いた場合の表示には対応）。参加経路で別途作られるトンネルの identityBlocker も v1 の ID 付与対象外です。
